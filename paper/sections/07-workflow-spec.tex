\subsection{Capability versus composition}
% \AgentStepClass (cluster-scoped, admin): kind = Action | Gate; executor,
%   image, command, timeout. Gate-only: blocking, fixAction (an Action class),
%   evidence format, scope (tree | diff). Action-only: turn and token budgets.
%   This is CAPABILITY. The kind split replaces a matrix of behavioural
%   booleans and makes the invalid combinations unrepresentable.
% \AgentWorkflow (namespaced, team): driver, steps (name, class, after,
%   invalidatedBy), budgets. This is COMPOSITION ONLY. A workflow step carries
%   no behavioural field at all -- there is nothing to reject because there is
%   nothing to write.
% Security consequence: a tenant authoring a workflow cannot introduce an
%   image, change what a step is, or weaken a gate. RBAC falls out: write on
%   workflows and tasks, read-only on classes and policy.

\subsection{Resolution and version pinning}
% Resolution: an explicit workflowRef [impl]; tag match, repo match, sole
%   workflow, default [spec, with the tracker connectors].
% SECURITY: never resolve from ticket free text. Body and comments are writable
% by anyone with issue access, including the agent. Resolve from trusted
% structured fields only, once, at admission, before any agent code runs.
% Pin the COMPLETE executable interpretation, not a hash: workflow, policy,
%   every referenced class by content, injected gates, budgets -- the resolved
%   plan, written once into status and frozen by a CEL transition rule.
%   Editing a workflow or a class mid-flight then cannot change a running
%   task's gate set, images or commands. State the trade-off honestly: a pinned
%   task keeps running a gate image an admin has since patched; superseding a
%   running task is a policy decision, not something pinning should be relaxed
%   to achieve.

\subsection{Admission without webhooks}
% Structural rules, enums and immutability transitions are CEL validation on
%   the CRDs; everything cross-object (class existence, kind consistency, DAG,
%   ceilings, injection) is controller admission -- authoritative because its
%   result is pinned in the same step. No certificates, no failure-policy
%   decisions, no race between a webhook's view and the controller's.
% Budgets above policy ceilings are rejected, never clamped. No policy present
%   admits nothing.

\subsection{Non-composable integrity requirements}
